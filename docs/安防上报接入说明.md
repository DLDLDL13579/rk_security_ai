## 一、快速启动

```bash
cd ~/rk_security_ai/rk_pose_authoritative
source security_mqtt.env          # 载入设备令牌与 brokers 配置
RK_HEADLESS=1 RK_POSE_BACKEND=rknn \

python app/main_security.py       # 用 ~/miniconda3/envs/rk3588_clean/bin/python
```

## 二、环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `RK_MQTT_TOKEN` | 空 | **设备 AccessToken（必需，缺失则只判定不上报）** |
| `RK_MQTT_BROKER` | 192.168.1.8 | IoTSharp 平台地址 |
| `RK_MQTT_PORT` | **1883** | MQTT 端口（注意：2927 是 Web 界面端口，不是 MQTT） |
| `RK_MQTT_TOPIC` | devices/me/telemetry | IoTSharp 直连设备话题 |
| `RK_SECURITY_ZONES` | 内置示例 | 区域 JSON 数组 |
| `RK_FIRE_SMOKE_MODEL` | 空 | 烟火模型路径（空=关闭烟火） |
| `RK_FALL_CONFIDENCE` | 0.55 | 跌倒判定置信度 |
| `RK_SECURITY_ENABLED` | 1 | 置 0 则退化为原 main_realtime.py |
| `RK_HEADLESS` | 0 | 无头模式（无显示器时必须置 1） |

## 三、区域配置格式

```json
[{"id": "zone_a", "name": "禁区", "type": "intrusion",
  "rect": [x1, y1, x2, y2], "loiter_seconds": 8.0}]
```

- `type` 取值：`intrusion`（仅入侵）/ `loiter`（仅逗留）/ `both`（两者）
- 判定锚点：人体检测框的**底边中心点**（`(x1+x2)/2, y2`）
- 坐标基于**原始分辨率**，非推理分辨率

## 四、事件类型

| 事件 | alert_type | 触发条件 |
|---|---|---|
| 跌倒 | `FALL_DETECTED` | 行为为 fall_down 且置信度 ≥ 阈值 |
| 区域入侵 | `INTRUSION_DETECTED` | 锚点首次进入 intrusion/both 区域 |
| 长时间逗留 | `LOITERING_DETECTED` | 在 loiter/both 区域停留 ≥ loiter_seconds |
| 火焰 | `FIRE_DETECTED` | 烟火模型检出 fire |
| 烟雾 | `SMOKE_DETECTED` | 烟火模型检出 smoke |

事件带冷却去重（默认 2 秒，区域事件 2 秒、烟火 1.5 秒）。

## 七、已实测结论（2026-09-29）

- 板端 → 平台上报：实机 60 秒 106 条、**零失败**；平台入库 1328 条
- 三类事件实机触发：入侵 6 次、逗留 6 次（多目标跟踪 id 4/5 独立判定）
- 烟火模型实机：加载 0.31s、推理 **87ms/帧**，同图同时检出 smoke(0.658) 与 fire(0.618)
- 网络：摄像头走 eth2、平台走 wlan0 `/32` 路由，**双通道并存**
