# rk_pose_authoritative 使用与维护说明

> 适用范围：`最新工程/rk_pose_authoritative`（权威工程，代码源自 `rk_pose_project _8.7`）
> 更新日期：2026-08-11

---

## 1. 这个工程是什么

RK3588 上的**多人实时行为识别**工程：对画面中的每个人分别识别 5 类行为（standing 站立 / walking 行走 / squat 下蹲 / bend 弯腰 / fall_down 跌倒）。

处理链路：

```
RTSP/视频文件
   │
   ▼
npU: YOLOv5s RKNN 检测（多人）          ← npu/yolo_rknn_v2.py + models/yolov5s-640-640.rknn
   │
   ▼
engine: SimpleTracker 分配稳定 ID       ← engine/tracker.py
   │
   ▼
姿态：每人裁剪 → MediaPipe 33 点        ← npu/mediapipe_pose.py
   │                                    （可选 RKNN 姿态：npu/pose_rknn.py + models/model.rknn）
   ▼
engine: 46 维特征 → 16 帧序列           ← engine/feature.py + engine/sequence_buffer.py
   │
   ▼
npu: TCN 行为模型（5 类先验）           ← npu/behavior_rknn.py + models/behavior_tcn.rknn
   │
   ▼
engine: 双通道判定（Locomotion/Special）← engine/locomotion_engine.py + engine/special_action_engine.py
   │
   ▼
display: 画框标注 / 无头录像             ← display/display.py
```

## 2. 怎么使用

### 2.1 一键演示（推荐）：`run_demo.sh`

```bash
bash run_demo.sh                                        # 默认视频 data/videos/walking/walk_001.mp4
bash run_demo.sh data/videos/standing/stand_002.mp4     # 指定视频
bash run_demo.sh rtsp://user:pass@ip:554/ch01           # 摄像头
bash run_demo.sh data/videos/standing/stand_002.mp4 --headless   # 无头录像 → output/behavior_result.mp4
```

注意：`--headless` 必须是第 2 个参数。脚本已锁定演示配置（MediaPipe 姿态、640×360、裁剪外扩 12%、跟踪平滑 0.65），均可被环境变量覆盖。

### 2.2 正式主程序：`app/main_realtime.py`

```bash
python app/main_realtime.py
# 或带环境变量：
RK_SOURCE=rtsp://admin:xxxx@192.168.1.64:554/Streaming/Channels/101 python app/main_realtime.py
RK_POSE_BACKEND=rknn RK_POSE_MODEL=.../model.rknn python app/main_realtime.py
```

内部三线程：`RTSPThread`（采集）→ `AIThread`（检测+行为）→ `DisplayThread`（显示/录像），另有 monitor 每 2 秒打印状态。所有默认路径自动基于工程根目录拼接。

### 2.3 批量评估：`run_eval_all.sh`

```bash
bash run_eval_all.sh    # 遍历 data/videos/ 全部视频 → output/eval_all_<时间戳>.csv
```

也可手动调用评估工具：

```bash
python eval/test_multi_behavior_eval.py --source data/videos --out output/eval.csv
python eval/test_multi_behavior_eval.py --source data/videos/standing/stand_002.mp4
python eval/test_multi_behavior_eval.py --source rtsp://user:pass@ip:554/ch01 --save-video 1
```

`--source` 传目录时按子目录名当标签，输出混淆统计；CSV 含 det 行（每帧检测框）、frame 行（每人行为）、summary 行（汇总指标）。

### 2.4 实时单人测试：`test/test_single_realtime.py`

```bash
python test/test_single_realtime.py
python test/test_single_realtime.py --source data/videos/walking/walk_001.mp4 --headless
```

窗口模式 ESC 退出，无头模式输出 `output/single_realtime_result.mp4`。

### 2.5 合成多人测试视频：`tools/make_multi_person_video.py`

```bash
python tools/make_multi_person_video.py \
    --left data/videos/standing/stand_001.mp4 \
    --right data/videos/walking/walk_001.mp4 \
    --out videos_multi/m1_stand_walk.mp4 --flip-right --height 480
```

两路单人视频左右拼成"两人同框"，用于验证多人跟踪/识别。

### 2.6 RTSP 录制：`tools/record_rtsp.py`

```bash
python tools/record_rtsp.py    # 录到 data/videos_camera/<名字>.mp4，ESC 停止
```

⚠️ 文件顶部 `RTSP_URL`（含账号密码）和 `VIDEO_NAME` 是写死的，使用前必须改，建议改为读环境变量。

### 2.7 板端小测试

```bash
python test/test_behavior_rknn.py       # 行为模型加载 + (16,46) 推理
python test/test_pose_rknn_single.py    # 姿态模型对 test/person.jpg 推理 → output/pose_test.jpg
python test/test_sequence_buffer.py     # 序列缓冲（仅需 numpy）
python npu/pose_rknn.py test/person.jpg # 直接看多人姿态输出（bbox+关键点）
```

### 2.8 PC 可跑的逻辑单测

```bash
python test/test_channels_logic.py      # 合成关键点，测 geometry/locomotion/special，无需 RKNN/MediaPipe
```

改 `RK_LOCO_*` / `RK_SPECIAL_*` 阈值后先跑它回归。

### 2.9 模型转换（PC）：`tools/onnx_rknn/convert_behavior_tcn.py`

```bash
cd tools/onnx_rknn
python convert_behavior_tcn.py --onnx behavior_tcn.onnx --calib-dir calib
python convert_behavior_tcn.py --verify
```

转换产物自动部署到 `models/behavior_tcn.rknn`。校准样本在 `calib/<类别>/`（每类 20 个）。

### 2.10 板端部署步骤

1. 整个目录复制到板端（例如 `/home/admin/rk_pose_authoritative`）；
2. `pip install -r requirements.txt`（rknnlite、opencv-python、mediapipe、numpy<2.0）；
3. 确认 `models/` 下三个 .rknn 存在；
4. `bash run_demo.sh` 先跑默认视频，再切 RTSP；
5. `bash run_eval_all.sh` 出评估 CSV 验收。

## 4. 现目前的问题（已知限制与风险）

### 4.1 运行环境

- **本机（Windows）无法真机验证**：无 rknnlite / mediapipe / numpy / cv2 环境，只能做语法与静态检查；实际推理必须到 RK3588 板端验收。
- 依赖版本敏感：`rknnlite` 必须与板端 RKNN 驱动（2.3.2）匹配，否则模型加载失败。

### 4.2 功能限制

- **多人 FPS 低**：当前姿态是 MediaPipe 逐人裁剪（CPU 串行），实测 3 人约 2.4 FPS；NPU 全帧路径（`PoseRKNN.detect_persons` + `RK_POSE_FULLFRAME=1`）代码已就绪，但需要真正的 YOLOv5-Pose RKNN 模型才能启用。
- **无 sit 类**：坐立会被判为 squat（近似）。
- **小目标/遮挡不可靠**：下肢关键点不可靠时靠可见性门兜底，但行为可能滞后或误判。
- **跟踪器无外观特征**：SimpleTracker 仅用 IOU/中心距离/面积比，遮挡交错时 ID 可能交换；升级需换 ByteTrack/DeepSort 等。
- **行为类别固定 5 类**：新增类别需要训练侧 + 转换 + 推理侧（`npu/behavior_rknn.py` 的 `class_names`、评估脚本 `CLASSES`）同步修改。

### 4.3 代码/工程问题

- **摄像头地址改用环境变量**（2026-09-28 已修）：`tools/record_rtsp.py` 等文件原先硬编码 RTSP 地址，现已改为读取 `RK_RTSP_URL` 环境变量，不再在代码中保存凭据。
- **特征一致性风险**：`engine/feature.py` 的 46 维特征必须与训练侧一致；改特征维度/顺序必须同时改训练工程并重新导出模型，否则行为模型输出无意义。
- **阈值标定靠现场**：`RK_LOCO_*` / `RK_SPECIAL_*` 大量阈值默认值基于演示数据，换场景/摄像头需要重新标定。
- **8.7 与权威版并存**：两套代码路径不同（videos/ vs data/videos/、npu/onnx-rknn vs models/），改代码时不要交叉引用，避免混淆；后续以权威版为准。
- **`core/` 是空壳**：预留抽象层，当前主流程未使用，接手人可忽略。

### 4.4 数据/输出

- `data/videos_camera/` 目前为空（RTSP 录制后才有内容）；
- `videos_multi/` 需用 `make_multi_person_video.py` 生成；
- 校准样本每类仅 20 个，量化精度不够时可补充每类 20~50 个真实样本；
- `output/` 为空目录，运行后自动写入。

### 4.5 建议的下一步（按优先级）

| 优先级 | 事项 |
|---|---|
| P0 | 板端验收：`test_behavior_rknn.py` → `run_demo.sh` → `run_eval_all.sh` |
| P0 | 把 `record_rtsp.py` 的凭据改成配置/环境变量 |
| P1 | 接入 YOLOv5-Pose RKNN，启用 `RK_POSE_FULLFRAME` 全帧姿态，解决多人 FPS |
| P1 | 用 `make_multi_person_video.py` 合成多人视频回归多人跟踪 |
| P2 | 升级跟踪器（ByteTrack/DeepSort）解决遮挡 ID 交换 |
| P3 | 按现场数据重新标定 `RK_LOCO_*` / `RK_SPECIAL_*` 阈值 |

## 5. 附录

### 5.1 常用环境变量速查

| 变量 | 默认值 | 作用 |
|---|---|---|
| `RK_SOURCE` | `data/videos/walking/walk_001.mp4` | 视频/RTSP 源 |
| `RK_POSE_BACKEND` | `mediapipe` | `mediapipe` / `rknn` |
| `RK_POSE_FULLFRAME` | `1` | 全帧姿态（后端支持才生效） |
| `RK_FRAME_WIDTH/HEIGHT` | `640/360` | 输入分辨率 |
| `RK_CROP_PAD` | `0.12` | 裁剪外扩 |
| `RK_MAX_BEHAVIOR_TRACKS` | `8` | 每帧最多行为目标 |
| `RK_DETECT_INTERVAL` / `RK_BEHAVIOR_LOOP_INTERVAL` | `0.015 / 0.06` | 推理节流 |
| `RK_HEADLESS` | `0` | 无头模式 |
| `RK_OUTPUT_VIDEO` | `output/behavior_result.mp4` | 无头录像路径 |
| `RK_LOCO_*` / `RK_SPECIAL_*` | 见 engine 代码 | 双通道阈值 |
| `RK_YOLO_MODEL` / `RK_POSE_MODEL` / `RK_BEHAVIOR_MODEL` | `models/*.rknn` | 模型路径覆盖 |

### 5.2 常见问题

| 现象 | 处理 |
|---|---|
| 画面空白 | 检查 `RK_SOURCE` 路径/RTSP 网络；先用 `record_rtsp.py` 测连通 |
| 行为迟迟不出 | 序列需要 1~2 秒积累（每人独立） |
| 一直站立/行走 | 姿态质量不足，调 `RK_POSE_QUALITY_THRESHOLD`、`RK_CROP_PAD` |
| 蹲/弯腰/跌倒不准 | 调 `RK_SPECIAL_*` 阈值 |
| 模型加载失败 | 核对 rknnlite 与 RKNN 驱动版本 |
| 量化后精度差 | 补充校准样本或 `--no-quantize` 对比 |
